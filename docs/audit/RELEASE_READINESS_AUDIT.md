# NexusIRL pre-release audit

**Verdict: NOT READY for broader public beta distribution of the audited revision.**

The strongest reason to hold the release is a reproduced credential disclosure. I imported a synthetic Moblin stream containing an OBS WebSocket password through NexusIRL’s compiled settings code. The password appeared both in the saved settings file and in the output of **Export without keys**. A user could follow the recommended sharing workflow and give someone their OBS password.

Two other findings affect the core streaming use case. A failed MP4 finalization can still be reported as a saved recording. When web remote control is enabled, an unauthenticated peer can consume an unbounded number of HTTP worker threads in the same process that is streaming.

The ordinary streaming paths have substantially better evidence. **All 448 reported local test executions passed, with zero skips**, including 14 ffmpeg interoperability cases. GitHub’s build, Gitleaks, CodeQL and Android emulator jobs also passed for this exact commit. The verdict concerns the specific failure paths below. It does not invalidate the reported real-phone field tests. ## 2. Security and privacy audit

**SEC-01 — Imported credentials cross the “without keys” boundary. HIGH · CONFIRMED.** Moblin explicitly encodes `obsWebSocketPassword`. NexusIRL preserves unknown stream fields for compatibility. The import and export paths protect a named set of fields, while `copy()` retains the extra fields. I exercised `SettingsStore.import()` and `exportJson(false)` using a temporary directory, an in-memory secret store and a synthetic password. Both the private settings JSON and the export contained the marker. The default export is the higher-impact exposure because users reasonably share it. Likelihood is high for an affected profile once it is exported. The minimal fix is to handle known upstream credential fields at import and migration, and to make the default export exclude opaque fields whose safety is unknown. Preserve full-fidelity round trips only through an explicitly sensitive path. **Regression:** import a real-shaped fixture, reload from disk, export without keys, and inspect the entire archive for synthetic markers, including nested and legacy fields. [Upstream encoder, line 1479](https://github.com/eerimoq/moblin/blob/97e26d2/Moblin/Various/Settings/SettingsStream.swift#L1479) · [Unknown-field serializer, lines 44–59](https://github.com/mesmerize08/NexusIRL/blob/b9eee46/core/codable/src/main/kotlin/io/github/mesmerize08/nexusirl/core/codable/SwiftPreserving.kt#L44-L59) · [Import, export and protection, lines 53–145](https://github.com/mesmerize08/NexusIRL/blob/b9eee46/app/src/main/kotlin/io/github/mesmerize08/nexusirl/settings/SettingsStore.kt#L53-L145)

**NET-01 — Unauthenticated HTTP connections can exhaust the streamer process. HIGH · HIGH-CONFIDENCE.** The listener submits each accepted socket to `newCachedThreadPool`. The ten-second timeout applies to individual reads. The 100-header check stops storing additional headers but continues reading them. A slow peer can retain workers by sending occasional bytes. The feature is off by default, so exposure requires the operator to enable it and the peer to reach its port. No denial-of-service attack was run against a device. Apply admission limits before dispatch, cap total header bytes and elapsed time, and close outstanding sockets during shutdown. **Regression:** maintain more slow unauthenticated connections than the configured limit, verify thread and descriptor counts stay bounded, authenticate a normal client, then stop the server and verify all workers exit. [HTTP server, lines 50–70 and 118–162](https://github.com/mesmerize08/NexusIRL/blob/b9eee46/remotecontrol/src/main/kotlin/io/github/mesmerize08/nexusirl/remotecontrol/RemoteControlWeb.kt#L118-L162)

**SEC-02 — A public hostname can pass the loopback exception. MEDIUM · CONFIRMED.** `isLoopback()` accepts any host string starting with `127.`. A DNS name such as `127.audit.example` therefore passes the guard regardless of its destination. The app permits cleartext globally and relies on client guards. Exposure requires such a URL to reach a guarded client. The defect establishes a transport-policy bypass; interception of a real token was not observed. Restrict the shortcut to validated loopback literals and verify the actual connection destination where name resolution is involved. **Regression:** public `127.`-prefixed hostname, normal loopback, mixed DNS answers, and HTTPS-to-HTTP redirects. [Address guard, lines 19–29 and 122–132](https://github.com/mesmerize08/NexusIRL/blob/b9eee46/core/websocket/src/main/kotlin/io/github/mesmerize08/nexusirl/core/websocket/CleartextPolicy.kt#L19-L29) · [Android network policy, lines 11–18](https://github.com/mesmerize08/NexusIRL/blob/b9eee46/app/src/main/res/xml/network_security_config.xml#L11-L18)

**SEC-03 — “Local network only” depends on the receiving interface more than the peer. MEDIUM · CONFIRMED.** `isLocalConnection()` accepts a private local destination address without requiring the remote address to be local or on-link. The Android wrapper excludes known cellular interfaces but permits a connection if interface lookup fails. A routed or port-forwarded connection can consequently reach authentication through a private Wi-Fi interface. The password or token still applies. This matters because the privacy policy explicitly promises local-only access, and the HTTP resource issue occurs before authentication. Check both ends of the connection, fail closed on unknown interfaces, and define the intended VPN/Tailscale exception explicitly. **Regression:** private local address with an off-link public source, forwarded traffic, missing interface metadata, legitimate hotspot, on-link public IPv6, and Tailscale. [Network predicate, lines 113–122](https://github.com/mesmerize08/NexusIRL/blob/b9eee46/core/websocket/src/main/kotlin/io/github/mesmerize08/nexusirl/core/websocket/CleartextPolicy.kt#L113-L122) · [Android interface check, lines 103–126](https://github.com/mesmerize08/NexusIRL/blob/b9eee46/app/src/main/kotlin/io/github/mesmerize08/nexusirl/remote/RemoteControlAssistantController.kt#L103-L126) · [Published privacy claim](https://github.com/mesmerize08/NexusIRL/blob/b9eee46/docs/privacy-policy.md#L45-L54)

**SEC-04 — WebSocket fragmentation needs an exact-version exposure test. MEDIUM · HYPOTHESIS for NexusIRL.** The project pins Java-WebSocket 1.5.7. An upstream report describes fragmented messages bypassing cumulative buffering limits in a later snapshot. NexusIRL uses the library for network listeners. I did not reproduce the issue against the pinned JAR, so this is a dependency investigation item, separate from the confirmed HTTP design in NET-01. Exercise the exact dependency with bounded heap before choosing a patch or mitigation. **Regression:** fragmented messages with many intermediate frames, including before application-level identification where the protocol allows it; assert bounded memory and continued service to another client. [Pinned version, line 21](https://github.com/mesmerize08/NexusIRL/blob/b9eee46/gradle/libs.versions.toml#L21) · [Upstream report](https://github.com/TooTallNate/Java-WebSocket/issues/1508) · [CVE record](https://osv.dev/vulnerability/CVE-2026-90584)

**Controls that held up in review.** Participating credential fields use Tink AES-256-GCM with Android Keystore wrapping. The app disables backup, enables `FLAG_SECURE` in release, redacts composed diagnostics, and shares reports through a non-exported `FileProvider`. The foreground service and isolated Kick login activity are non-exported. The launcher accepts `moblin://` setup links with an in-app confirmation flow. The web remote requires its token, uses a constant-time comparison, and refuses browser-originated settings imports. These controls narrow exposure. They do not cover the unknown-field path in SEC-01. Kick’s website session also has materially broader authority than a scoped OAuth token, as the project’s threat model acknowledges. ## 3. Performance and reliability audit

**MED-01 — Failed MP4 finalization can produce a false “saved” result. HIGH · CONFIRMED.** `write()` catches `IllegalStateException` and marks the writer stopped, but the video caller still increments `videoFrames`. At shutdown, `playable` is computed before `muxer.stop()`, and the exception handler leaves it true. `StreamController.stopRecording()` uses that result to clear MediaStore’s pending flag. This is most likely during storage exhaustion or a muxer failure, precisely when the operator needs an accurate result. Count successful writes only, retain failure state, and publish only after successful finalization. **Regression:** fail the first video write, fail after several good frames, and fail `stop()` independently. In each case verify the UI result, MediaStore visibility, file-descriptor cleanup and continued live streaming. [Recorder, lines 125–157](https://github.com/mesmerize08/NexusIRL/blob/b9eee46/media/pipeline/src/main/kotlin/io/github/mesmerize08/nexusirl/media/pipeline/Mp4Recorder.kt#L125-L157) · [Publication, lines 515–532](https://github.com/mesmerize08/NexusIRL/blob/b9eee46/app/src/main/kotlin/io/github/mesmerize08/nexusirl/stream/StreamController.kt#L515-L532)

**MED-02 — A stalled TLS handshake can outlive RTMPS cancellation. MEDIUM · HIGH-CONFIDENCE.** The default socket factory applies a TCP connection timeout, then calls `startHandshake()` without an explicit handshake read deadline. The connection object receives the socket only after the factory returns. During that interval, the twenty-second protocol timer can close the logical connection without access to the underlying socket. A peer that accepts TCP and never answers TLS can leave an I/O thread behind across retries, subject to the platform TLS implementation. Expose the socket to cancellation before handshaking, set a handshake deadline, and close it on every failure path. **Regression:** a controlled server accepts TCP and sends no TLS bytes. Repeat cancel/reconnect and assert socket and thread counts return to baseline. [TLS factory, lines 69–82](https://github.com/mesmerize08/NexusIRL/blob/b9eee46/transport/rtmp/src/main/kotlin/io/github/mesmerize08/nexusirl/transport/rtmp/RtmpStream.kt#L69-L82) · [Connection ownership, lines 551–582 and 625–637](https://github.com/mesmerize08/NexusIRL/blob/b9eee46/transport/rtmp/src/main/kotlin/io/github/mesmerize08/nexusirl/transport/rtmp/RtmpStream.kt#L551-L582)

**MED-03 — LUT import applies its size limit after allocating the file. MEDIUM · CONFIRMED.** The importer calls `readBytes()` before checking the 64 MiB limit. The image path then decodes the bitmap and allocates a second pixel array before validating the LUT’s shape. A selected oversized document or small compressed image with extreme dimensions can exhaust the process heap. A process crash was not induced. Enforce the byte cap while reading, inspect dimensions before decode, and bound the pixel count. **Regression:** unknown-length stream exceeding the cap by one byte, a small image with oversized dimensions, and valid LUTs at the supported boundary. [LUT loader, lines 49–78](https://github.com/mesmerize08/NexusIRL/blob/b9eee46/app/src/main/kotlin/io/github/mesmerize08/nexusirl/scene/LutLoader.kt#L49-L78)

**MED-04 — SRT data sequence numbers enter the control-packet range. LOW · CONFIRMED.** The sender increments with a 32-bit mask, while the packet classifier treats a set top bit as a control packet. A sufficiently long uninterrupted session crosses `0x7fffffff`. The pinned Swift sender uses a wrapping `UInt32` too. This is unlikely in ordinary field sessions and is a case where matching upstream is insufficient. Use 31-bit data-sequence arithmetic consistently, including comparison and retransmission windows. For encrypted streams, coordinate rollover with key refresh or a fresh session so the same key and counter are never reused. **Regression:** seed near rollover and exercise data, ACK, NAK and encrypted transfer across the boundary with a reference peer. [Sender, lines 307–310](https://github.com/mesmerize08/NexusIRL/blob/b9eee46/transport/srt/src/main/kotlin/io/github/mesmerize08/nexusirl/transport/srt/SrtSender.kt#L307-L310) · [Packet classifier, line 52](https://github.com/mesmerize08/NexusIRL/blob/b9eee46/transport/srt/src/main/kotlin/io/github/mesmerize08/nexusirl/transport/srt/Srt.kt#L52) · [Pinned upstream sender](https://github.com/eerimoq/moblin/blob/97e26d2/Moblin/Media/HaishinKit/Srt/SrtSender.swift#L383-L388)

**PERF-01 — A started GL handoff can wait indefinitely. MEDIUM · HYPOTHESIS for a user-visible ANR.** The handoff timeout cancels work that has not started. Once the GL thread begins the block, its caller waits without a deadline. Encoder attach/detach can execute EGL surface operations inside that block. The ownership logic prevents releasing a surface underneath GL, which should be preserved. A vendor EGL call that stalls after starting can nevertheless hold a UI-initiated operation indefinitely. Move potentially blocking waits off the UI thread while retaining single ownership of cleanup. **Regression:** suspend the GL operation after it enters the block, initiate record/stop from the UI, and verify UI responsiveness and exactly-once eventual cleanup. No ANR rate or performance penalty was measured. [Handoff, lines 20–46](https://github.com/mesmerize08/NexusIRL/blob/b9eee46/media/pipeline/src/main/kotlin/io/github/mesmerize08/nexusirl/media/pipeline/Handoff.kt#L20-L46) · [Encoder attach and detach, lines 226–281](https://github.com/mesmerize08/NexusIRL/blob/b9eee46/media/pipeline/src/main/kotlin/io/github/mesmerize08/nexusirl/media/pipeline/VideoPipeline.kt#L226-L281)

### Architecture and operational boundaries

The Android app is split into 17 Gradle modules. `:app` owns Compose UI, lifecycle, permissions, streaming orchestration and MediaStore publication. `:settings`, `:effects` and `:chat` hold configuration, effect models and platform clients. The four `:core` modules provide Swift-compatible serialization, clocks/executors, secrets and WebSockets. `:media:pipeline` owns Android capture, GL and codecs; `:media:mux` owns elementary-stream and MPEG-TS formatting. `:transport:srt`, `:transport:rtmp` and `:transport:abr` implement network output and bitrate control. `:net`, `:moblink` and `:remotecontrol` handle interface binding and control protocols. The two command-line modules are the push tool and SRTLA receiver. The repository also contains optional self-hosted server configuration. [Module inventory](https://github.com/mesmerize08/NexusIRL/blob/b9eee46/settings.gradle.kts)

The video path is Camera2 → SurfaceTexture → GL compositor → encoder surface → MediaCodec output. AudioRecord feeds the audio encoder; consumers share encoded audio. The sinks route encoded media to MPEG-TS over SRT/SRTLA, FLV over RTMP(S), or local MP4 recording. The recording path waits for track configuration and the first video keyframe. Stream sessions recreate destinations on reconnect and reject stale callbacks by generation. Important ownership boundaries are the camera callback, GL handler, codec drain threads, serial transport executors and recording lock. Notably, the RTMP queue has a **100 MB outstanding-byte disconnect threshold**. The remaining risk is the memory available to a particular phone before that threshold is reached, especially with several destinations. [Media pipeline](https://github.com/mesmerize08/NexusIRL/blob/b9eee46/media/pipeline/src/main/kotlin/io/github/mesmerize08/nexusirl/media/pipeline/VideoPipeline.kt) · [Session and reconnect lifecycle](https://github.com/mesmerize08/NexusIRL/blob/b9eee46/app/src/main/kotlin/io/github/mesmerize08/nexusirl/stream/StreamSession.kt) · [RTMP byte accounting](https://github.com/mesmerize08/NexusIRL/blob/b9eee46/transport/rtmp/src/main/kotlin/io/github/mesmerize08/nexusirl/transport/rtmp/RtmpStream.kt#L709-L721)

The interoperability tests provide direct evidence for codec headers, mux output, timestamp handling and reception by ffmpeg/libsrt under their test conditions. The two shaped-network ABR tests are particularly relevant to IRL streaming. They do not establish HEVC hardware rate-control accuracy across vendors, sustained thermal performance, RTMPS cancellation, or recovery of interrupted Android MP4 files. The changelog records real field problems involving camera contention, bitrate overshoot, microphone selection and hotspot interoperability. Those are the best scenarios to repeat on the eventual release candidate. [Field changes](https://github.com/mesmerize08/NexusIRL/blob/b9eee46/CHANGELOG.md#L20-L69)

## 4. Release engineering, Android compatibility and test coverage

**REL-01 — Release publication has weaker gates than branch CI. MEDIUM · CONFIRMED.** The release workflow runs tests, but does not explicitly install ffmpeg or require it. It also verifies multiple signed APKs in a loop piped to `tee`, without an explicit per-APK failure check. A verification failure for one ABI can be masked by later output. Printing certificate information does not assert that every APK has the expected signer. This is conditional on tagging a revision without successful equivalent CI, missing tooling, or one bad artifact. Require success for the tagged SHA, enforce ffmpeg, and fail individually on an invalid signature, wrong signer or unexpected version. **Regression:** dry-run with one invalid APK, one differently signed APK, and unavailable ffmpeg. Each must prevent publication. Drain asynchronously or redirect to a file before the timed wait. **Regression:** use a silent child that never exits and verify termination at the configured deadline. ## 5. Prioritised remediation plan

1. **Close the credential disclosure first.** Add the reproduced OBS case to the release gate, inventory the other credential-bearing fields in the pinned upstream schema, and cover settings already imported by existing users. A fix limited to future imports leaves existing exports exposed.
2. **Make recording success trustworthy.** Separate “frames were offered,” “frames were written,” and “the MP4 finalized.” Exercise the failure paths while a live stream is running.
3. **Bound the remote-control listener before broader distribution.** Test unauthenticated connection pressure, enforce the intended peer boundary, and assess the pinned WebSocket dependency in the same network test setup.
4. **Harden cancellation and release verification.** Test silent RTMPS peers, reject oversize LUTs before allocation, and make every per-ABI signature and transport-test check fail closed.
5. **Qualify the signed candidate.** Re-run the automated gate on the exact SHA, then use the matrix for upgrades, interrupted recordings and targeted field validation. Retain receiver-side evidence alongside phone diagnostics so a successful UI status can be checked against what viewers actually received.

The first three items are the conditions for reconsidering broader beta distribution. The credential round-trip, recording fault injection, and listener admission tests can all progress without a physical phone.
